# Theme Manifest

## Overview

The theme manifest is the single registry of the stylesheets the themes package ships. It exports the `ThemeKey` string-literal union, the `ThemeEntry` shape (`id`, `label`, `css`), the `themes` record that maps each key to its entry, and `themeIds`, the list of keys. Each entry's `css` is the stylesheet text imported from the generated `theme-data` module (its header reads "AUTO-GENERATED by scripts/build-theme-data.mjs — do not edit"). The manifest holds data only: it applies nothing to a document.

A theme is usable only once it is registered here. The comment in `rescued-themes.test.ts` states that the registry (`ThemeKey`, `themes`, `themeIds`) is the only path any consumer, including the demo site's theme picker, has to reach a theme. `ThemeStyle` reads `themes[theme]` to emit a style element, and several tests iterate `themeIds` over the real stylesheets.

## Behavioral Requirements

### Types

- **theme-key-union**: `ThemeKey` MUST be a closed union of exactly the 39 string literals listed in the Registered themes table.
- **theme-entry-shape**: `ThemeEntry` MUST carry `id` (a `ThemeKey`), `label` (a string) and `css` (a string).

### Registry

- **themes-record-total**: `themes` MUST be a `Record<ThemeKey, ThemeEntry>` with one entry for every `ThemeKey`; the compiler rejects a missing or extra key.
- **entry-id-matches-key**: Every entry's `id` MUST equal the key it is stored under. The type system does not enforce this, because `id` is typed `ThemeKey` rather than the record key; each entry is written out by hand.
- **entry-label-human**: Every entry's `label` MUST be the display name shown in the Registered themes table, including the non-ASCII forms `ADH · Comic` (middle dot) and `Rosé Pine`, and `Synthwave '84` with a straight apostrophe.
- **entry-css-nonempty**: Every entry's `css` MUST be the non-empty stylesheet string exported by `theme-data` under the name in the table's last column. The manifest does not check for emptiness itself; the test `rescued-themes.test.ts` asserts it for `crt-monitor` and `handheld-communicator`.
- **css-source-generated**: The manifest MUST NOT embed stylesheet text; it MUST import every stylesheet from `./theme-data`, the generated module.
- **unknown-key-lookup**: Looking up a key that is not in `themes` MUST yield `undefined`; the manifest provides no fallback, default theme or error. `ThemeStyle` handles that case by rendering nothing.

### Key list

- **theme-ids-derived**: `themeIds` MUST be `Object.keys(themes)` cast to `ThemeKey[]`, so it contains each of the 39 keys exactly once.
- **theme-ids-order**: `themeIds` MUST follow the declaration order of the `themes` literal (the order of the Registered themes table), not alphabetical order.
- **theme-ids-computed-once**: `themeIds` MUST be computed once at module load; adding a key at run time to `themes` does not update it.

### Module surface

- **manifest-exports**: The module MUST export `ThemeKey`, `ThemeEntry`, `themes` and `themeIds`. The package `index.ts` re-exports exactly these four from `./manifest`.
- **no-side-effects**: Importing the module MUST NOT touch the DOM, storage, network or files; its only effect is evaluating the imported stylesheet strings.
- **no-ordering-rules**: The manifest MUST NOT define a default theme, a grouping or a sort; consumers that need those own them.

## Edge Cases

- **Null and empty input**: The module takes no input. A lookup with an empty string, `undefined` or `null` yields `undefined` from the record; the consumer MUST handle it (`ThemeStyle` renders nothing for an unknown key).
- **Boundary values**: Display names include non-ASCII characters (middle dot, `é`) and an apostrophe; they MUST be preserved exactly. `themeIds` has a fixed length of 39.
- **Key and id drift**: An entry whose `id` differs from its record key compiles. This is a hand-maintenance risk the types do not catch; the only runtime check is the test for the two rescued themes. Consumers MUST NOT assume it is verified for every theme.
- **Missing registration**: A stylesheet in `theme-data` that nobody lists in the manifest is unreachable and invisible, per the comment in `rescued-themes.test.ts`. A key that is listed but whose export is missing fails at build time.
- **Concurrent access**: Not applicable: the module is evaluated once, holds constants and has no asynchronous operation. Nothing prevents a consumer from mutating `themes` or `themeIds`, since neither is frozen.
- **Error states and offline**: Not applicable: the module reads no file, network or storage at run time; the stylesheet text is bundled at build time through imports.
- **Large payload**: The manifest imports all 39 stylesheets as strings, so importing it loads every theme's text, even if only one is used. The source has no lazy loading.

## Platform Notes

- **SwiftUI**: Start from a Swift enum with a `String` raw value that conforms to `CaseIterable` and `Identifiable`; `allCases` plays the role of `themeIds` and a computed `label` property replaces the entry. Native themes are asset catalogs or token structs rather than CSS text, so `css` becomes a palette value; there is no need for a runtime string stylesheet.
- **Compose**: Use an enum class or sealed interface of theme keys, each carrying its label and a `ColorScheme` or `Typography` set, with `entries` as the key list. Compose themes are code, so the CSS string has no counterpart; keep the identifier strings stable for persisted choices.
- **React/Web**: The source is `packages/web/packages/themes/src/manifest.ts`, which imports generated string constants from `theme-data.ts` and is re-exported from the package `index.ts`. The record is typed `Record<ThemeKey, ThemeEntry>` so the compiler checks completeness, and `Object.keys` supplies the id list. The package also exposes it as the `./manifest` subpath. Consumers are `ThemeStyle.tsx`, the adh package (`theme-keys.ts` reads `themes`; `adh-themes.ts` takes `ThemeKey` as a type only), the persona package, and tests that iterate the corpus.
- **AppKit / UIKit**: Model it as a Swift enum, as for SwiftUI, with `NSColor` or `UIColor` palettes; on macOS apply a theme through `NSAppearance` plus custom color assets, and on iOS through trait collections. No runtime stylesheet exists, so the manifest becomes an enum with a palette per case.
- **WinUI 3**: Represent each theme as a `ResourceDictionary` XAML file and register them in a C# class: `enum ThemeKey`, a `record ThemeEntry(ThemeKey Id, string Label, Uri Source)` and a `static readonly IReadOnlyDictionary<ThemeKey, ThemeEntry> Themes` built in a static initializer. Expose `ThemeIds` as an `ImmutableArray<ThemeKey>` when order matters (a plain `Dictionary` does not guarantee order). A picker binds an `ObservableCollection<ThemeEntry>` to a `ComboBox` or `GridView` and swaps the active dictionary by replacing an item in `Application.Current.Resources.MergedDictionaries`. The CSS text is replaced by `ResourceDictionary` brushes keyed per `ThemeDictionaries` (`Light`, `Dark`, `HighContrast`).

## Design Decisions

**Decision**: Register themes in a hand-written record whose `ThemeKey` union is maintained separately from it.
**Rationale**: Inferred from the source: the union gives consumers literal-type keys, and `Record<ThemeKey, ThemeEntry>` makes the compiler enforce that every key has an entry. The cost is that each key is written three times and `id` is not tied to the record key.
**Approved**: pending

**Decision**: Derive `themeIds` from `Object.keys(themes)` instead of a second hand-kept array.
**Rationale**: The source derives it, so the list cannot drift from the record; it follows declaration order, which is why the keys are not alphabetical.
**Approved**: pending

**Decision**: Hold stylesheet text as imported strings from a generated `theme-data` module instead of loading files at run time.
**Rationale**: The `ThemeStyle` comment says the style element is rendered inline so it is in the server-rendered HTML and applied on first paint; bundling the text makes that possible. The cost is that every theme is loaded with the manifest.
**Approved**: pending

**Decision**: Make registration the gate for a theme to exist.
**Rationale**: The `rescued-themes.test.ts` comment states a stylesheet on disk is invisible until it is registered, so the manifest is the one place to add a theme.
**Approved**: pending
