
Theme Data is `theme-data.ts` in the themes package: a generated module with one exported string constant per stylesheet in the package's `src/styles` directory. Its first line says it is generated by `scripts/build-theme-data.mjs` and must not be edited. The script (its text comes from `renderThemeData` in `scripts/theme-data.mjs`) reads each `.css` file, replaces every relative `@import` with the text of the file it names, and writes the result as a JSON-quoted string, so each constant is the whole stylesheet a page needs.

The strings exist so that a component can put a theme into the document as raw text. `ThemeStyle` ([adhsdk.ingredient.themes.theme-style](cookbook:54b48020-df78-4b41-853c-268ad0ea6b84)) injects them through the manifest ([adhsdk.ingredient.themes.manifest](cookbook:391a4eef-9872-432f-a049-eac4af00938d)), and a consumer that cannot run a CSS bundler can still use them. Every sheet the manifest registers is one export, and every other sheet in the directory is still exported but not registered. As a snapshot of the current source, the module has 43 exports: 39 are registered themes, and four are shared sheets that are not themes (`accessibilityCss`, `colorModeLightCss`, `fishlampPaletteCss` and `mikefullertonLandingCss`). Treat these numbers as a snapshot; the requirements below do not depend on them.

The module holds data only. It has no functions, types or behavior, so most behavioral requirements below describe the generator's contract and the shape of what it emits.
