# Theme Data

## Overview

Theme Data is `theme-data.ts` in the themes package: a generated module with one exported string constant per stylesheet in the package's `src/styles` directory. Its first line says it is generated by `scripts/build-theme-data.mjs` and must not be edited. The script (its text comes from `renderThemeData` in `scripts/theme-data.mjs`) reads each `.css` file, replaces every relative `@import` with the text of the file it names, and writes the result as a JSON-quoted string, so each constant is the whole stylesheet a page needs.

The strings exist so that a component can put a theme into the document as raw text. `ThemeStyle` injects them through the manifest, and a consumer that cannot run a CSS bundler can still use them. The module has 43 exports: 39 are registered themes that the manifest imports, and four are shared sheets that are not themes (`accessibilityCss`, `colorModeLightCss`, `fishlampPaletteCss` and `mikefullertonLandingCss`).

The module holds data only. It has no functions, types or behavior, so most behavioral requirements below describe the generator's contract and the shape of what it emits.

## Behavioral Requirements

### Generated shape

- **generated-header**: The first line of the file MUST be the comment `// AUTO-GENERATED by scripts/build-theme-data.mjs — do not edit.`, followed by one blank line.
- **one-export-per-sheet**: The file MUST contain exactly one `export const` for each `.css` file in `src/styles`, and no other export.
- **export-value-type**: Each export MUST be a single string literal, written with `JSON.stringify`, so line breaks, quotes and backslashes in the CSS are escaped.
- **export-name**: An export name MUST be the file name without `.css`, with each hyphen followed by a lowercase letter replaced by that letter in uppercase, plus the suffix `Css`.
- **export-name-digits**: A hyphen followed by anything other than a lowercase letter MUST be left in place by the name conversion; no shipped file name triggers this case.
- **export-order**: Exports MUST appear in ascending order of the sorted file names, so `adh-comic.css` precedes `adh.css` because the hyphen sorts before the period.
- **trailing-newline**: The file MUST end with a single newline after the last export.
- **non-theme-sheets**: The file MUST also carry the sheets that are not registered themes, because the script reads every file in the directory without a filter beyond the `.css` extension.
- **non-ascii-preserved**: Characters outside ASCII, such as the em dash in a comment, MUST be written as they are, not as `\u` escapes.

### Stylesheet content

- **relative-import-inlined**: A relative `@import` of the form `@import './x.css';` (or with double quotes, and `./` or `../`) MUST be replaced by the full text of that file, recursively, so no exported string contains a relative `@import`.
- **remote-import-kept**: A remote `@import url(...)` MUST be left in the string unchanged; 35 of the exports begin with or contain one for a web font request.
- **self-hosted-fonts-kept**: A sheet that declares `@font-face` MUST keep the declaration in its string; `adhCss`, `adhIosevkaCss`, `charcoalCss` and `fishlampCss` do.
- **shared-palette-copied**: A sheet that imports another sheet MUST carry that sheet's text inside its own string; `fishlampCss` and `mikefullertonLandingCss` each contain the full text of `fishlampPaletteCss`.
- **import-position-preserved**: The inlined text MUST sit exactly where the `@import` statement was, with the text before and after it unchanged.
- **css-otherwise-verbatim**: Apart from import inlining, the string MUST equal the file's text, with no minification or rewriting.

### Generator

- **runs-from-package-root**: The script MUST read from `src/styles` and write to `src/theme-data.ts`, both resolved against the current working directory, so it MUST be run from the themes package root.
- **overwrite-output**: The script MUST replace any existing `src/theme-data.ts` in full.
- **completion-message**: On success the script MUST print `build-theme-data: N themes → src/theme-data.ts`, using `theme` when N is 1 and `themes` otherwise.
- **self-import-error**: When a stylesheet imports itself, directly or through a chain of relative imports, the script MUST throw an error whose message is `inline-imports: <path> imports itself`.
- **missing-import-target**: When a relative `@import` names a file that does not exist, the script MUST fail with the file system's read error and MUST NOT write the output file.
- **deterministic-output**: The same set of CSS files MUST produce a byte-identical output file, because the script uses no timestamp, random value or environment input.
- **generated-in-sync**: The file on disk MUST equal what `renderThemeData` in `scripts/theme-data.mjs` renders from the current stylesheets. The test `themeDataInSync.test.ts` renders it and compares, so a stylesheet edited without regenerating fails the test suite instead of shipping stale CSS.

### Lifecycle and consumption

- **not-committed**: `src/theme-data.ts` MUST NOT be committed; the package's ignore file lists it and the `clean` script deletes it.
- **regenerated-on-install**: The package's `postinstall` script MUST run the generator, so a workspace that links the package has the file after install.
- **script-ships-with-package**: The package's `files` list MUST include `scripts/build-theme-data.mjs`, `scripts/theme-data.mjs` and `scripts/inline-imports.mjs`, because `postinstall` needs all three in a copy made by a deploy.
- **manifest-is-consumer**: The manifest MUST import 39 of the exports, one per theme key, and expose each as the `css` of its `ThemeEntry`.
- **no-other-source-consumer**: The four sheets that are not themes MUST NOT be imported by the manifest; they are reachable only by importing `theme-data` directly or by loading the `.css` file.
- **consumers-stub-in-tests**: A test that does not need the CSS SHOULD stub the module instead of importing it, because the file is generated and gitignored, so a test that imports it depends on whether the themes package has been built (the comment in `settingsTab.test.tsx` says this).

### Ordering and concurrency

Not applicable: the module is constants evaluated once at import. The generator is one sequential run that reads files one at a time and writes once; it has no shared mutable state.

## Appearance

Not applicable: the module is generated data with no rendering. The look of each theme is specified by the stylesheet it carries, not by this file.

## States

Not applicable: the module has no interactive or visual state. The only states are that the file exists or does not exist, which the lifecycle requirements cover.

## Accessibility

Not applicable: the module renders nothing. Its `accessibilityCss` string carries the reduce-motion, contrast and text-size rules, but those are specified by the appearance recipe, and this module only transports the text unchanged.

## Edge Cases

- **Empty styles directory** (MUST): with no `.css` file the script writes the header, a blank line and a trailing newline only, and prints `build-theme-data: 0 themes → src/theme-data.ts`.
- **Empty stylesheet** (MUST): an empty `.css` file yields an export whose value is the empty string.
- **Non-CSS files in the directory** (MUST): a file without the `.css` extension is ignored.
- **Name collision** (not handled): two file names that convert to the same export name, such as `a-b.css` and `aB.css`, would produce a duplicate `export const`; the source does not detect it, and no shipped file collides.
- **Circular import chain** (MUST): a chain `a.css` to `b.css` to `a.css` throws the self-import error rather than recursing forever.
- **Import in a comment** (not handled): the import pattern is matched as text, so a relative `@import` inside a CSS comment is inlined too; `charcoalCss` and `fishlampCss` mention `@import` in comments without a relative path and are unaffected.
- **Import resolves outside the directory** (MUST): a `../` import is resolved against the importing file's directory, so it may read a file outside `src/styles`.
- **Wrong working directory** (MUST): run from another directory, the script resolves `src/styles` there, fails to read it, and writes nothing.
- **Missing file at runtime** (MUST): before the first install or build the file does not exist, so a source-path import of it fails; this is why the package runs the script on `postinstall`.
- **Concurrent runs**: not applicable beyond overwriting; two simultaneous runs write the same bytes to the same path, so the result is the same.
- **Network and offline**: not applicable to the generator, which only reads local files; the remote `@import url(...)` lines it keeps are fetched later by the browser, and a failed font fetch is the browser's concern.
- **Large strings** (MUST): the largest exports are `crtMonitorCss` (about 58,000 characters) and `handheldCommunicatorCss` (about 56,000); the whole file is held in memory and written in one call.

## Platform Notes

- **SwiftUI**: There is no direct equivalent; a native app has no stylesheet strings. Start from a generated Swift file or an asset catalog of named colors per theme, produced by a script from the same token sources, and pick the set with an `Environment` value or a shared `ObservableObject`. The source is CSS text; Swift needs typed color and font values instead.
- **Compose**: Generate a Kotlin file of `ColorScheme` objects (one `lightColorScheme` and `darkColorScheme` pair per theme) from the token sources with a Gradle task, and choose one for `MaterialTheme`. Typed values replace the raw CSS strings, so nothing is injected as text.
- **React/Web**: The source is `packages/web/packages/themes/src/theme-data.ts`, produced by `scripts/build-theme-data.mjs`, which writes the text `scripts/theme-data.mjs` renders with `scripts/inline-imports.mjs`, then imported by `manifest.ts`. The file is gitignored and built on `postinstall`, `build`, `dev` and `lint`. It is plain ES module constants, so it works under any bundler and in a server render.
- **AppKit / UIKit**: Generate a Swift source or asset catalog per theme and apply it through `NSAppearance` or named colors on macOS, or `UIColor` assets with trait collections on iOS. The text-injection step has no counterpart; theme switching changes the appearance of native views directly.
- **WinUI 3**: Express each theme as a `ResourceDictionary` XAML file with `ThemeDictionaries` keyed `Light` and `Dark`, holding `SolidColorBrush` and `Color` resources and font `FontFamily` values. Merge the chosen dictionary into `Application.Resources.MergedDictionaries` at startup, and swap it at runtime by replacing the merged entry. A build step (an MSBuild target or a script) can generate the dictionaries from the token sources the way the Node script generates strings, and the CSS `@font-face` blocks map to `FontFamily` URIs such as `ms-appx:///Assets/Fonts/Iosevka.ttf#Iosevka`. Because XAML has no relative-import inlining to perform, `MergedDictionaries` plays the part of `inlineImports`, referencing a shared palette dictionary from each theme.

## Design Decisions

**Decision**: Emit each stylesheet as a string constant in a generated module rather than import the CSS file.
**Rationale**: The comment in `build-theme-data.mjs` says the strings are for `ThemeStyle`'s raw injection, which needs the text at runtime in code that runs without a CSS bundler.
**Approved**: pending

**Decision**: Inline relative `@import` statements and leave remote ones alone.
**Rationale**: The comment in `inline-imports.mjs` says a sheet that shares another's roles holds only its own declarations, so anything that reads it as a whole theme must inline the import; a remote font request is not a file the script can read, so the browser keeps resolving it.
**Approved**: pending

**Decision**: Regenerate the file on install and keep it out of version control.
**Rationale**: The package comments say `postinstall` runs the script so any workspace that links the package gets the file, and the ignore file lists it, which also explains why tests that do not need it stub the module.
**Approved**: pending

**Decision**: Export every `.css` file, including sheets that are not themes.
**Rationale**: Inferred from the script, which has no filter; it keeps the generator trivial, at the cost that sheets such as `accessibilityCss` and `colorModeLightCss` sit beside the theme strings and are not registered in the manifest.
**Approved**: pending

**Decision**: Sort file names before generating.
**Rationale**: Inferred from the script's explicit sort; it makes the output order independent of the directory listing order of the file system.
**Approved**: pending

The generated module keeps one concern: it holds stylesheet text and nothing else, while reading, import inlining and writing sit in three small scripts and the choice of theme sits in the manifest, so separation of concerns passes. No test sits beside the module or the generator; the manifest-level tests only prove the strings are non-empty and parse as the expected stylesheets, so unit-test coverage fails. `themeDataInSync.test.ts` re-renders the file through the same `renderThemeData` the generator uses and compares it with the file on disk, so post-generation verification passes. The inliner reports a self-import clearly, but a missing import target surfaces as a raw file system error and a duplicate export name is not detected, so explicit error handling is partial.
