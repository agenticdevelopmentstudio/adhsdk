
- **SwiftUI**: read the available width via `GeometryReader`, compute `min(proposedWidth - gutter, measure)` (mirroring `#requirements/constrains-width`), with `@ScaledMetric var gutter = 40` so it scales with type size, and apply that as an explicit `.frame(width:)` centered with `.frame(maxWidth: .infinity, alignment: .center)`. A separate `.frame(maxWidth: measure).padding(.horizontal)` applies the gutter inside the measure cap instead of choosing the smaller of the two, and does not reproduce the source's behavior.
- **Compose**: compute `min(constraints.maxWidth - gutterPx, measurePx)` (with `gutterPx` converted from a `2.5.rem`-equivalent `sp` value so it scales with font size) in a custom `Layout` (or `Modifier.layout`) and constrain the child to that computed width before centering. `Modifier.widthIn(max = measure).padding(horizontal = gutter)` applies the gutter inside the measure cap rather than choosing between the two alternatives, and does not reproduce the source's behavior.
- **React/Web**: React functional component. Accepts `children: ReactNode` and `className?: string`, combined via `['lp-wrap', className].filter(Boolean).join(' ')`. Width and centering come from the `.lp-wrap` rule derived in `#appearance`.
- **AppKit / UIKit**: constrain the content to an explicit width constraint computed as `min(superview width - gutter, measure)`, with the gutter derived from a font-relative value such as `UIFontMetrics.scaledValue(for: 40)` (on AppKit, scale it from the system font size), centered in its superview, rather than subclassing `NSView` / `UIView`. A fixed readable-width constraint plus separate edge insets has the same mismatch as the SwiftUI/Compose notes above.
- **WinUI 3**: bind `MaxWidth` to a value computed as `Math.Min(availableWidth - gutter, measure)` (mirroring `#requirements/constrains-width`), with the gutter scaled from the text scale factor (`UISettings.TextScaleFactor`) applied to 40, `HorizontalAlignment="Center"`. A static `MaxWidth` set to `measure` plus a separate fixed `Padding` for the gutter applies the gutter inside the cap instead of choosing the smaller of the two, and does not reproduce the source's behavior. Wrap holds one content tree, not a collection, so no `VisualStateManager` or visibility converters are needed.
