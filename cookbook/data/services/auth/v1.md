# Auth v1 Wire Conventions

## Overview

This module holds the conventions every adh client shares when it talks to the `/v1` API, in the lowest tier that holds an authenticated HTTP client. The `/v1` API is shaped after Stripe's: a collection answers a list envelope paged by an object-id cursor, a DELETE answers a tombstone, `created` and `updated` are unix seconds while every other timestamp stays an ISO string, and `include[]` folds a sub-resource into a read.

The module exports two envelope types (`V1List`, `V1Deleted`), one constant (`V1_PAGE_MAX`), and five functions: `withV1Query`, `listAllV1`, `listV1Page`, `unixToIso` and `isoToUnix`. `listAllV1` is the one place that walks a collection to its end; a caller that needs every row calls it rather than looping `starting_after` itself. Every request goes through `authedJson` from the Authentication Client ([adhsdk.ingredient.data.services.auth.auth-client](cookbook:3ea9329e-5acc-4c43-b5ce-bb8c50570104)) recipe, so bearer-token attachment and the single refresh-and-retry on a 401 are inherited, not reimplemented here.

## Behavioral Requirements

### Data shapes

- **list-envelope**: A `V1List<T>` MUST have the fields `object` (the literal `'list'`), `data` (an array of `T`), `has_more` (boolean) and `url` (string).
- **deleted-tombstone**: A `V1Deleted` MUST have the fields `id` (string), `object` (string) and `deleted` (the literal `true`). The module declares this type only; it contains no function that issues or parses a DELETE.
- **page-max**: `V1_PAGE_MAX` MUST equal 100, the widest page `/v1` serves.
- **timestamp-convention**: `created` and `updated` values on the wire MUST be treated as unix seconds, and every other timestamp as an ISO string. This is stated in the module header and enforced by no code other than the two conversion functions.

### withV1Query

- **query-append**: `withV1Query(url, params)` MUST return `url` with each entry of `params` added to its query string, and MUST return the path unchanged with no `?` when the resulting query string is empty.
- **query-drop-nullish**: `withV1Query` MUST skip a param whose value is `null` or `undefined`, leaving any same-named key already in `url` untouched.
- **query-replace**: `withV1Query` MUST replace a key already present in `url`'s query string when `params` supplies a non-nullish value for it, so a cursor can be advanced on a URL that carries one.
- **query-array-repeat**: `withV1Query` MUST emit one `key=value` pair per element when a param value is an array (for example `include[]=a&include[]=b`), after removing every earlier occurrence of that key.
- **query-empty-array**: `withV1Query` MUST remove an existing key and add nothing when a param value is an empty array, because the delete runs before the append loop.
- **query-stringify**: `withV1Query` MUST convert string, number and boolean values (and array elements) with `String(value)`.
- **query-encoding**: `withV1Query` MUST serialize the query string with `URLSearchParams`, so the key `include[]` is written percent-encoded as `include%5B%5D`, and a space is written as `+`.
- **query-preserves-fragment**: `withV1Query` MUST keep a `#fragment` at the end of the returned URL and MUST NOT parse it as part of the query.
- **query-preserves-existing-order**: `withV1Query` SHOULD leave unrelated existing query keys in their original order; a replaced key is deleted and re-appended, so it moves to the end of the query string.

### listAllV1

- **walk-all-pages**: `listAllV1<T>(url, init, opts)` MUST fetch successive pages of `url` and return their rows concatenated in the order received, stopping when a page reports `has_more` false.
- **page-size**: `listAllV1` MUST request every page with `limit=100` (`V1_PAGE_MAX`), replacing any `limit` already in `url`.
- **cursor-advance**: `listAllV1` MUST send `starting_after` set to the cursor of the previous page's last row on every page after the first, and MUST NOT add `starting_after` on the first page. A `starting_after` already present in `url` is left in place on the first page and replaced on every later page.
- **cursor-default**: When `opts.cursorOf` is not supplied, the cursor of a row MUST be its `id` converted with `String`, provided the row is a non-null object whose `id` is a string or a number; any other row has no cursor.
- **cursor-custom**: When `opts.cursorOf` is supplied, `listAllV1` MUST use it in place of the default to derive the cursor from the last row of each page.
- **keep-filters**: `listAllV1` MUST preserve every other query parameter already on `url` (for example `ecosystem_id=e1`) on every page request.
- **init-passthrough**: `listAllV1` MUST pass `init` unchanged to every page request. It does not set the HTTP method, so the request is a GET only because `init` normally carries no method.
- **stop-on-empty-page**: `listAllV1` MUST return the rows gathered so far when a page's `data` is empty, even if that page reports `has_more` true.
- **tolerate-malformed-page**: `listAllV1` MUST treat a page whose `data` is not an array as an empty page, and a missing page body (null or undefined) as an empty page with `has_more` false.
- **truncation-guard**: `listAllV1` MUST throw an `Error` whose message is `<url>: has_more is set but the last row carries no id to page from` when `has_more` is true, the page is non-empty and the last row has no cursor, rather than returning a silently truncated list. The message carries the caller's original `url`, not the paged one.
- **no-loop-guard**: `listAllV1` SHOULD NOT be relied on to detect a server that keeps returning `has_more` true with the same last row; it has no page cap, no repeated-cursor check, no timeout and no cancellation, so such a server makes the loop run until the caller's request fails.
- **error-propagation**: `listAllV1` MUST let any error thrown by `authedJson` (for example `AuthHttpError` with the HTTP status, or a network `TypeError`) propagate out unchanged and MUST discard the rows already gathered.

### listV1Page

- **single-page**: `listV1Page<T>(url, init)` MUST issue exactly one `authedJson` request for `url` exactly as given, adding no `limit` or `starting_after`.
- **page-unwrap**: `listV1Page` MUST return `{ data, hasMore }`, where `data` is the page's `data` array or `[]` when it is not an array, and `hasMore` is true only when the page's `has_more` is strictly `true`.
- **page-error-propagation**: `listV1Page` MUST let any error thrown by `authedJson` propagate unchanged.

### unixToIso and isoToUnix

- **unix-to-iso**: `unixToIso(seconds)` MUST return `new Date(seconds * 1000).toISOString()` for a finite number, so `0` yields `1970-01-01T00:00:00.000Z`.
- **unix-to-iso-nullish**: `unixToIso` MUST return `null` for `null`, `undefined`, `NaN`, `Infinity` and `-Infinity`. The first overload types a plain number argument as returning a string; the second types a nullable argument as returning `string | null`.
- **unix-to-iso-range**: `unixToIso` MUST let the `RangeError` from `Date.prototype.toISOString` propagate for a finite number outside the JavaScript date range (an absolute value above 8.64e12 seconds); the function does not catch it.
- **iso-to-unix**: `isoToUnix(iso)` MUST return `Math.floor(Date.parse(iso) / 1000)`, truncating sub-second precision toward negative infinity.
- **iso-to-unix-invalid**: `isoToUnix` MUST return `NaN` for a string `Date.parse` cannot read; it does not validate its input or throw.

### Ordering and concurrency

- **sequential-pages**: `listAllV1` MUST fetch pages strictly one after another, because each request needs the previous page's last-row cursor. Concurrent `listAllV1` calls are independent; the module keeps no shared state.
- **single-threaded**: The module is single-threaded JavaScript. Its synchronous helpers (`withV1Query`, `unixToIso`, `isoToUnix`) have no ordering rule to define.

### Side effects

- **network-only**: The only side effect MUST be the HTTP requests `authedJson` makes. The module does not read or write storage, tokens, files or notifications, does not log, and does not mutate its inputs.

### Security

- **credential-source**: Bearer credentials are attached, and a 401 is refreshed and retried once, inside `authedJson`; this module MUST NOT read, store or log a token. Token lifetime, storage and revocation are specified in the Authentication Client ([adhsdk.ingredient.data.services.auth.auth-client](cookbook:3ea9329e-5acc-4c43-b5ce-bb8c50570104)) recipe.
- **url-as-given**: The module MUST send requests to the `url` the caller passes and MUST NOT rewrite its origin; the caller owns choosing a same-origin proxy path or an authorization-server base.
- **sensitive-data-in-url**: The only caller-supplied data this module places in a URL is the paging cursor (an object id) and caller params. It MUST NOT be given secrets as params, because the URL is part of the thrown error message from `listAllV1`.

## Edge Cases

- **Null and empty input, empty collection**: MUST return `[]` from `listAllV1` when the first page has empty `data`, whatever `has_more` says (stop-on-empty-page).
- **Null and empty input, missing body**: MUST treat a null or undefined parsed body as an empty page with no more rows; `authedJson` itself throws on a 204 response before this module sees it.
- **Null and empty input, query params**: MUST ignore `null` and `undefined` param values and MUST remove a key given an empty array (query-drop-nullish, query-empty-array). An empty `params` object returns `url` with its existing keys and values, re-serialized through `URLSearchParams` (so a `%20` in an existing value comes back as `+`).
- **Malformed input, bad page shape**: MUST fall back to an empty `data` array when the server sends a non-array `data`; the module does not report the malformation.
- **Malformed input, bad timestamp**: `isoToUnix` returns `NaN` for an unparseable string and `unixToIso` returns `null` for a non-finite number; a caller that persists the result MUST check for both.
- **Boundary values, page size**: MUST always request `limit=100`; a caller-supplied `limit` in `url` is overwritten. `listV1Page` sends no `limit`, so the page size is whatever `url` carries or the server defaults.
- **Boundary values, timestamps**: `unixToIso` accepts negative seconds (pre-1970) and fractional seconds; the result carries millisecond precision. `isoToUnix` floors, so a fractional second is lost and a pre-1970 instant rounds toward earlier time.
- **Boundary values, cursor types**: A numeric `id` is accepted as a cursor and stringified; an `id` of `null`, an object or a boolean yields no cursor.
- **Error states, truncation**: MUST throw rather than return a partial list when `has_more` is true and the last row has no cursor (truncation-guard).
- **Error states, HTTP failure**: MUST propagate the `authedJson` error (an `AuthHttpError` carrying status, code and body, or a network error) and discard partially collected rows. The module adds no retry beyond the one refresh-and-retry inside `authedJson`.
- **Error states, runaway server**: The module has no page cap or repeated-cursor detection, so a server that never clears `has_more` while changing nothing keeps the loop requesting (no-loop-guard). This is the module's behavior; the gateway owns the correctness of `has_more`.
- **Concurrent access**: Not applicable to shared state, because the module holds none; two concurrent `listAllV1` calls each walk their own cursor. A collection mutated between page requests can yield a row twice or skip one, which the cursor design does not prevent; the `/v1` gateway owns that guarantee.
- **Offline or disconnected state**: A request that fails because the network is down rejects with the fetch error and aborts the walk (error-propagation); there is no queueing, caching or resume.
- **Cancellation and timeout**: Neither is supported; `init.signal` is passed through to each page request, so a caller MAY abort by supplying an `AbortSignal`.
- **Request method**: `init` is passed through without forcing GET, so an `init` carrying another method or a body is sent as given on every page.

## Platform Notes

- **SwiftUI**: Port the envelope as `Codable` structs (`V1List<T: Decodable>`, with `CodingKeys` mapping `has_more` to `hasMore`) and `listAllV1` as an `async throws` loop over `URLSession` with `URLComponents`/`URLQueryItem` in place of `withV1Query`; array params become repeated `URLQueryItem`s. Unlike `URLSearchParams`, `URLComponents` leaves `[` and `]` unescaped unless encoded by hand, so encode `include[]` explicitly if the gateway compares bytes. Use `Date(timeIntervalSince1970:)` with `ISO8601DateFormatter` (fractional seconds enabled) for the timestamp pair; `Date` does not throw on out-of-range seconds, so the range edge case needs an explicit check.
- **Compose**: Use `kotlinx.serialization` data classes with `@SerialName("has_more")`, a `suspend fun` loop over an OkHttp or Ktor client, and `HttpUrl.Builder.setQueryParameter`/`addQueryParameter` (set replaces, add repeats) for `withV1Query`. Convert times with `Instant.ofEpochSecond` and `Instant.toString()` (which drops zero fractional seconds, where `toISOString` always writes `.000Z`, so format with a fixed three-digit millisecond pattern to match); `Instant.parse` throws on bad input where the source returns `NaN`, so catch `DateTimeParseException` to match.
- **React/Web**: This is the source platform: `packages/web/packages/auth/src/v1.ts`, re-exported from `client.ts`, with tests in `packages/web/packages/auth/src/__tests__/v1.test.ts`. It carries the `'use client'` directive, depends on `authedJson` from `./client`, and uses the platform `URLSearchParams` and `Date`. Because `URLSearchParams.toString()` encodes brackets, `include[]` goes out as `include%5B%5D`, and a replaced key moves to the end of the query.
- **AppKit / UIKit**: Same Foundation approach as SwiftUI: an `async throws` function over `URLSession.data(for:)`, a `URLComponents` builder, and `JSONDecoder` with `keyDecodingStrategy` set to `convertFromSnakeCase`. For completion-handler call sites wrap the async function in a `Task`; nothing in the contract requires the main thread.
- **WinUI 3**: Use `System.Net.Http.HttpClient` (one shared instance, with a `DelegatingHandler` adding the bearer header and the single refresh-and-retry on 401 that `authedJson` provides) and `System.Text.Json` with `[JsonPropertyName("has_more")]` on a generic `V1List<T>` record and `JsonSerializerOptions` that tolerate a missing body. Implement `ListAllV1Async<T>` as an `async Task<IReadOnlyList<T>>` loop that awaits one page at a time and accepts a `CancellationToken` (the source has no cancellation; pass it to `GetAsync`). Build query strings with `System.Web.HttpUtility.ParseQueryString` (a `NameValueCollection`: `Set` replaces, `Add` repeats) or `QueryHelpers.AddQueryString`, noting that `HttpUtility` encodes a space as `+` and brackets as `%5b`/`%5d` (lowercase hex, unlike `URLSearchParams`). Convert times with `DateTimeOffset.FromUnixTimeSeconds` and `ToString("o")`, which throws `ArgumentOutOfRangeException` where the source throws `RangeError`; use `DateTimeOffset.TryParse` and `ToUnixTimeSeconds` for the reverse, returning `null` instead of `NaN`. If the port runs inside a WinUI app, keep the loop off the UI thread by awaiting it from a view-model command and updating an `ObservableCollection<T>` only after it completes, since the source returns the full list in one piece.

## Design Decisions

**Decision**: `listAllV1` is the only function that walks a collection; callers do not loop `starting_after` themselves.
**Rationale**: The module header states it is the one place that does, so the cursor and `has_more` handling lives once and a fix reaches every caller.
**Approved**: pending

**Decision**: `listAllV1` throws when `has_more` is true and the last row has no id, instead of returning what it has.
**Rationale**: The gateway pages by id, so a row with no id cannot advance the cursor; the doc comment says it throws "rather than returning a silently truncated list", trading a visible failure for an invisible data loss.
**Approved**: pending

**Decision**: `listAllV1` requests the maximum page size of 100 on every page and overwrites a caller-supplied `limit`.
**Rationale**: Fewest round trips for a full walk; the page size is fixed by `V1_PAGE_MAX`, the widest page the gateway serves, so a caller wanting a smaller page uses `listV1Page`.
**Approved**: pending

**Decision**: `withV1Query` deletes a key before setting or appending it, which replaces a repeated key and moves it to the end of the query.
**Rationale**: The doc comment says a key already in the URL is replaced so a cursor can be advanced on a URL that carries one; the delete-then-set order makes that true for arrays as well. The side effect is reordering, noted by query-preserves-existing-order.
**Approved**: pending

**Decision**: Malformed page bodies degrade to empty pages instead of throwing.
**Rationale**: `Array.isArray(page?.data)` guards and `has_more === true` in `listV1Page` make the helpers tolerant of a null or malformed body. The cost is that a broken gateway response looks like an empty collection; the source does not report it. The `has_more === true` strict check in `listV1Page` differs from the truthiness check in `listAllV1`, so a truthy non-boolean `has_more` such as `'true'` continues the walk in `listAllV1` but reports `hasMore` false in `listV1Page`.
**Approved**: pending

**Decision**: `unixToIso` is overloaded so a plain number returns a string and a nullable input returns a nullable string, and it maps non-finite input to `null` rather than throwing.
**Rationale**: Optional `/v1` timestamps (`updated` may be absent) can be converted in one call. The range `RangeError` is left uncaught, so the null mapping covers missing or non-finite values only.
**Approved**: pending

**Decision**: The module has no timeout, page cap, retry or cancellation of its own.
**Rationale**: Transport concerns belong to `authedJson` and the caller's `init`; the one refresh-and-retry on a 401 comes from there. A caller needing a deadline passes an `AbortSignal` in `init`.
**Approved**: pending

**Decision**: The module is documented against `adh`'s Stripe-shaped `/v1` API, and the matching server conventions (DELETE tombstone, `include[]` expansion) are described but not implemented here.
**Rationale**: `V1Deleted` and the `include[]` convention are declared for client use; the gateway owns their server side, and `withV1Query` is the client half of `include[]`.
**Approved**: pending
