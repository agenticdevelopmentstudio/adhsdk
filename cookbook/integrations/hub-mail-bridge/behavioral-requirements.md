
- **one-entry-point**: `respond(to:)` MUST answer every `MailRequest` with a `MailResponse` and never throw; a failure becomes `.failure(message)`, and a missing account, message or thread becomes `.notFound(message)`.
- **client-transport**: `client` MUST be a `MailClient` whose transport decodes the request with `JSONDecoder`, answers it with `respond(to:)` and encodes the response with `JSONEncoder`, the same coding the daemon transport uses.
- **provider-configured**: `providerStatus` MUST answer configured with no client id, because the OAuth client is the hub's, not the app's.
- **admin-refused**: `importOAuthClient`, `removeProvider`, `signIn`, `cancelSignIn`, `removeAccount` and `updateSettings` MUST answer `.failure` saying Gmail accounts are managed on the hub, and change nothing.
- **accounts-from-connections**: `listAccounts` MUST answer one account per connection in `HubMailStore.connections()`, in that order, with the connection id as `id`, status active, default sync settings, no error, and as `lastSyncAt` the bridge's `lastSyncAt()` (nil when none was given), so a reader polling `listAccounts` sees each completed pull.
- **account-address**: An account's `email` MUST be the address of the `from` of its newest live message labelled `SENT` (the part inside `<…>` when there is one), lowercased; with no such message it MUST be the connection id.
- **account-lookup**: An `account` argument MUST match a connection by id, else by its derived address ignoring case; no match MUST answer `.notFound("unknown account: …")`.
- **labels-mapped**: `listLabels` MUST answer the connection's labels in the store's order, each with the provider label id as `id` and its name, type, parent name and counts.
- **label-resolution**: A label argument MUST resolve to a provider label id by exact id, else by exact (case-sensitive) name, among the connection's labels, without duplicates; any other value MUST answer `.failure("unknown label: …")`.
- **messages-filtered**: `listMessages` MUST answer the connection's live messages newest first, narrowed to those carrying every label in `labels`, at least one label in `anyLabels` when it is non-empty, and an `internal_date` within `since`...`until` (inclusive) when given, a page of at most the filter's clamped `limit`.
- **opaque-cursor**: `nextCursor` MUST be set exactly when more messages follow, as an opaque string that the same filter takes back as `cursor` to continue; a cursor that does not decode MUST answer `.failure("bad cursor")`.
- **any-labels-applied**: The page MUST set `appliedAnyLabels` when `anyLabels` resolved to at least one label.
- **query-refused**: A filter with a non-blank `query` MUST answer `.failure` saying search is not available for mail read through the hub, because the mirror cannot run Gmail's search syntax and a local text match would silently misread it.
- **bodies-on-request**: Message bodies MUST be included only when asked: always for `getMessage`, per `includeBodies` for `listMessages` and `getThread`. The text body is `body_text` unless it is blank, then the HTML body read as text.
- **message-mapping**: A message MUST map with the hub row id as `id`, the provider id as `gmailId`, the thread id (empty when missing), the account's address, `from` (empty when missing), recipients, label ids and their names (a label with no known name keeps its id), subject and snippet (empty when missing, the snippet's HTML entities decoded), `internal_date` as `date` (empty when missing), the class from `MailClassifier.classify(labelIds:)`, and the attachment references decoded from the attachments JSON (none when it does not decode).
- **message-lookup**: A message id MUST match a live message of the connection by hub row id, else by provider id; no match MUST answer `.notFound("unknown message: …")`.
- **thread-lookup**: `getThread` MUST take a thread id, or a message id standing for that message's thread, and answer the thread's live messages oldest first with the thread id as `id`; neither MUST answer `.notFound("unknown thread: …")`.
- **modify-through-hub**: `modifyLabels` MUST resolve every message and label first, then post one `modify_labels` action for the connection with the messages' provider ids and the resolved add and remove ids, then write the same change into the mirror, and answer the messages as they now stand, in request order. With nothing to add or remove it MUST post nothing and answer the messages unchanged.
- **move-through-hub**: `moveMessages` MUST add `destination` and remove every label in `from`, where the labels removed are decided by `from`: a `from` that is given removes exactly those labels; a `nil` `from` removes INBOX when the destination is not INBOX; a `nil` `from` removes nothing when the destination is INBOX. A destination that is also in `from` MUST answer `.failure`. Every requested message MUST be written, in one action, even one the mirror shows already moved, because the mirror can lag Gmail and the hub's change is idempotent; every message MUST get a result naming, by label name, what was added and removed as measured against the mirror just before the write.
- **write-failure**: When the hub refuses a label write or answers a result whose `ok` is false, the bridge MUST answer `.failure` carrying that result's `error` text, or "the hub did not change the labels" when it has none, and leave the mirror unchanged.
- **mirror-write**: Writing a label change into the mirror MUST keep each row's sync version, so the next pull of that row from the hub replaces it.
- **sync-now**: `syncNow` MUST run one pull through the hub sync, for any account argument, and answer `.ok`.
- **service-stable-client**: `HubMailService.client` MUST be one `MailClient` for the service's lifetime: while connected it answers through the current bridge; otherwise every request MUST answer `.failure(HubMailService.signedOutMessage)`.
- **service-sign-in**: `signedIn()` MUST call `connect` once, build a bridge over the sync's store, set `.connected`, attach a periodic trigger when `syncInterval` is set, and pull once. A call while connected MUST do nothing; a throwing `connect` MUST set `.failed` with its message and leave the client signed out.
- **service-sign-out**: `signedOut()` MUST stop answering through the bridge at once, stop the trigger, set `.signedOut`, purge the mirror through `HubMailSync.signOut()` and stop the engine. A purge failure MUST set `.failed` saying the copy could not be cleared. Called while `.failed` with no sync, it MUST return to `.signedOut`.
- **service-purge-left-over**: `signedOut()` with no mirror open (a launch whose restore ended signed out, or a failed sign-in) MUST still open the mirror through `connect` and purge it the same way, so mail a previous launch's identity left on disk is never served to the next identity; a `connect` that throws MUST leave the status `.signedOut`.
- **service-sign-in-waits**: `signedIn()` MUST wait for a `signedOut()` purge still running before it opens the mirror, and a second `signedOut()` MUST wait for the first, so no purge ever deletes rows a newer sign-in pulled.
- **service-renews-refused-token**: while connected, the service MUST read the sync's events. On `.authRequired` it MUST call the connection's `refreshSession` and, when that returns true, pull again at once with a manual kick (the engine drops other kicks while paused for auth). When the renewal returns false, or the hub refuses the pull again before a cycle completes, it MUST set `.failed(HubMailService.authRetryMessage)`, keep answering reads from the mirror, and pull again after `authRetryDelay`. The next completed cycle (`.idle`) MUST return the status to `.connected`, and every completed cycle MUST record its time (ISO 8601 with fractional seconds) as the `lastSyncAt` the service's bridge reports. Sign-out MUST cancel the watch and any scheduled pull.
- **service-follows-session**: `follow(_:)` MUST sign in on `.signedIn`, sign out on `.signedOut`, and leave the mirror alone on `.restoring` and `.error`.
- **service-status-callback**: `onChange` MUST be called on the main actor once for every change of `status`, and never when it is set to the value it already has.
- **live-shares-session**: `HubMailService.live` MUST build one `SessionController` that both the returned `HubAccount` and the service follow, pull with the stored session's credentials, renew a refused pull's session by calling the hub client (whose middleware rotates the stored session the pulls read), and send label writes through the same client. The database MUST open on the first sign-in or the first sign-out (whichever comes first), creating its folder, and stay open.
- **live-at-location**: `HubMailService.live(at:syncInterval:)` MUST build the same session as `live(databaseURL:deviceId:syncInterval:)`, with the location's `databaseURL` and `deviceId`, `syncInterval` defaulting to 300, and the default Keychain session store and bundle sign-in configuration.
- **location-value**: `HubMailLocation` MUST carry a `databaseURL` and a `deviceId` and compare equal when both match.
- **location-app-file**: `HubMailLocation.app(_ appFolder:)` MUST put the mirror at `<Application Support>/<appFolder>/hub-mail.db`, the first Application Support directory of the user domain, in its own file apart from every other database the app keeps, so signing out purges hub mail alone. It MUST NOT create the folder; the first sign-in or sign-out does.
- **location-device-id**: `HubMailLocation.deviceId(defaults:key:)` MUST return the string stored under `key` (default `hub_mail_device_id`), or, when there is none or it is empty, make a new UUID string, store it under `key` and return it, so the same device keeps one id and the hub resumes its cursor. `app(_:defaults:deviceIdKey:fileManager:)` MUST take its `deviceId` from this rule, from `UserDefaults.standard` unless told otherwise.
- **routed-client**: `MailClient.routed(_:)` MUST call its picker for every request and send that request through the client it returns, so a source switch takes effect on the next request.
