
- **SwiftUI**: The source is `packages/apple/AgenticDeveloperHubSDK/Core/Process/ProcessEnv.swift` in the `AgenticDeveloperHubSDKCore` target; it imports only Foundation and Darwin and has no SwiftUI content. It reads launch data with `sysctl` (`KERN_PROCARGS2`, `KERN_PROC_PID`). The cache is a static dictionary marked `nonisolated(unsafe)` and guarded by an `NSLock`; tests use `cachedTokenCountForTesting` and `resetCacheForTesting()`.
- **Compose**: Android has no way to read another app's environment; within one app, use `/proc/<pid>/environ` and `/proc/<pid>/cmdline` (NUL-separated) for same-uid processes on a rooted or same-app case, and `/proc/<pid>/stat` for the parent pid. Guard a `LinkedHashMap` cache with a `Mutex` and evict by timestamp as the source does.
- **React/Web**: Node: read `/proc/<pid>/environ` on Linux, or run `ps eww -p <pid>` on macOS (the source's comment cites it as proof the data is readable); `process.ppid` gives only the current process's parent. A browser cannot do this.
- **AppKit / UIKit**: The same `sysctl` calls work on macOS. iOS sandboxing forbids reading another process's launch data, so this does not port to UIKit. Under the macOS app sandbox the read can fail and yield nil, which callers already treat as "unknown".
- **WinUI 3**: A process's environment and parent are not available through a simple .NET API. Use `NtQueryInformationProcess` with `ProcessBasicInformation` for the parent pid (`InheritedFromUniqueProcessId`) and read the PEB's `ProcessParameters` environment block with `ReadProcessMemory` (needs `PROCESS_QUERY_INFORMATION | PROCESS_VM_READ`, allowed for same-user processes); `System.Diagnostics.Process.GetProcessById` supplies names and the main module's file name. Parse the UTF-16 environment block (`KEY=VALUE` entries separated by NUL, ended by an empty entry) in place of the byte-offset walk. Keep the cache in a `Dictionary<int, (DateTime At, string Token)>` guarded by `lock`, with the same 128 and 30-second rules.
