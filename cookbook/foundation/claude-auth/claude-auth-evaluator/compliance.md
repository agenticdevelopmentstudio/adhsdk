`separation-of-concerns` passes: the evaluator only decides, the HTTP exchange lives in `ClaudeTokenRefresher`, attribution lives in `AccountFingerprints`, storage of rotations lives in the app, and serialization of rounds lives in `AccountQuotaProbe`. `unit-test-coverage` is partial: no test sits beside the toolkit copies; the identical predecessors are covered by Stenographer's `ClaudeTokenEvaluatorTests` and `AccountFingerprintsTests`, and the toolkit's `AccountQuotaObserveTests` covers `publish` and `accountName` through `CredentialFence`, but the margin-widening, foreign-error detail length, failure-status expiry, concurrency timing, request shape, rotation fold and cache concurrency vectors have no test anywhere. `explicit-error-handling` is partial: every refresh failure is caught, classified, logged and returned, but `publish` discards a failure to set 0600 (the open question on `publish-permissions-failure`). `error-response-handling` passes because each endpoint answer maps to a distinct, documented state with a one-line detail. `timeout-configuration` passes: each exchange has a 15-second timeout. `retry-with-backoff` fails: there is no retry within a call, deliberately, since a retried refresh may spend a token the first attempt already rotated; the next call is the only retry. `fault-tolerance` passes because one credential's failure never affects another's judgment and a bad fingerprints file degrades to "no match". `idempotent-operations` is partial: classification, status, `refusal`, `rotated`, `merge` and lookups are pure or repeatable, but `evaluate` and `renew` spend single-use refresh tokens, and concurrent calls (and a duplicate login inside one round, the open question on `duplicate-login-in-one-round`) are not guarded. `data-integrity` is partial: fingerprints are written atomically, but concurrent publishers lose merges and a corrupt file is overwritten without its history. `token-lifecycle` passes: expiry margin, single-use rotation, revocation (`.spent`), the 8-hour default life and the refusal to refresh without a storage address are all handled. `secure-transport` passes: the exchange goes only to an HTTPS URL with the token in the body. `secure-storage` is partial: no token is stored, and the fingerprints file holds only digests and names at 0600, but that mode is set after the atomic write and its failure is ignored. `secure-log-output` passes: no token is ever logged. `no-pii-in-logs` is partial: the account email is logged with public privacy. `data-minimization` passes: readers get digests, never tokens, and statuses are secret-free. `caching-strategy` passes: the lookup cache invalidates on path, mtime and size. `main-thread-freedom` passes because every refreshing entry point is `async` and the network work runs in child tasks; the fingerprint lookup is a synchronous file stat plus, on change, a small read.
