
- **controlled-value**: In the Wrapper, the component MUST accept a `value` prop of type boolean that reflects the current checked state (`Checkbox.tsx`, `value` prop on `CheckboxProps`).
- **change-callback**: In the Wrapper, the component MUST accept an `onChange` callback that is invoked with the new boolean value when the user toggles the input (`Checkbox.tsx`, `onChange` prop; the input's `onChange={(e) => onChange(e.target.checked)}` handler).
- **switch-appearance**: In the Wrapper, the component MUST support an `appearance` prop set to `'switch'` to render a switch-mode toggle with `role="switch"` on the input (`Checkbox.tsx`, `appearance` prop; `role={appearance === 'switch' ? 'switch' : undefined}`).
- **check-appearance**: In the Wrapper, the component MUST support an `appearance` prop set to `'check'` to render a checkbox-mode input without the switch role (`Checkbox.tsx`, same `role` expression).
- **default-appearance**: In the Wrapper, the component MUST default the `appearance` prop to `'switch'` when not specified (`Checkbox.tsx`, `appearance = 'switch'` default parameter).
- **disabled-state**: In the Wrapper and the Primitive, the component MUST accept a `disabled` prop that prevents user interaction when true. The Wrapper's native `<input>` carries the standard `disabled` attribute (`Checkbox.tsx`, `disabled={disabled}`) and its source adds no dimming of its own. The Primitive (`checkbox.tsx`) forwards `disabled` to Base UI's `CheckboxPrimitive.Root`, which renders as a `<span role="checkbox">` carrying `aria-disabled`/`data-disabled` with `tabindex="-1"` and blocks toggling internally; because `:disabled` never matches that span, the Primitive MUST style the state with `data-[disabled]:pointer-events-none data-[disabled]:opacity-50`, so a disabled box renders at 50% opacity and ignores pointer events.
- **optional-label**: In the Wrapper, the component MUST conditionally render a label element when the `label` prop is provided as a ReactNode (`Checkbox.tsx`, `label` prop; `{label && <span className="aws-checkbox__label">{label}</span>}`).
- **optional-hint**: In the Wrapper, the component MUST conditionally render a hint element when the `hint` prop is provided as a ReactNode (`Checkbox.tsx`, `hint` prop; `{hint && <p className="aws-field__hint">{hint}</p>}`).
- **label-input-association**: In the Wrapper, the component MUST use a `htmlFor` attribute on the label element to associate it with the input's `id`, generating a unique ID when no explicit `id` is provided (`Checkbox.tsx`, `fieldId = id ?? generatedId` from `useId()`; `<label htmlFor={fieldId}>` and `<input id={fieldId}>`).
- **visual-indicator**: In the Primitive, it MUST render a visual checkmark indicator that appears only when checked (`checkbox.tsx`, `CheckboxPrimitive.Indicator` wrapping a Lucide `Check` icon). The wrapper's own `<span className="aws-checkbox__indicator aws-checkbox__indicator--{appearance}">` (`Checkbox.tsx`) has no icon child; its checked appearance is applied entirely by stylesheet rules outside these two files.
- **checked-without-color**: In the Primitive, it MUST signal the checked state by the `Check` glyph in addition to the `apt-gold` fill, so the state is distinguishable without relying on color alone (`checkbox.tsx`, `data-[checked]:bg-apt-gold` on the Root; the `Check` icon in the Indicator).
- **focus-ring**: In the Primitive, it MUST display a visible focus indicator when the input receives keyboard focus (`checkbox.tsx`, `focus-visible:ring-2 focus-visible:ring-apt-gold/25` on the Root; React/Web renders this as a 2px ring at 25% opacity using the `apt-gold` token).
- **custom-classname**: In the Wrapper and the Primitive, the component MUST accept a `className` prop and apply it to its root container — the wrapper's outer `<div>` (`Checkbox.tsx`, `cls` array joined with `.filter(Boolean).join(' ')`) and, independently, the primitive's `CheckboxPrimitive.Root` (`checkbox.tsx`, `className={cn(..., className)}`).
- **custom-id**: In the Wrapper, the component MUST accept an `id` prop that is passed to the input element for label association (`Checkbox.tsx`, `id` prop; `fieldId = id ?? generatedId`).
- **controlled-and-uncontrolled**: In the Primitive, it MUST accept `checked` and `onCheckedChange` props for controlled mode, or `defaultChecked` for uncontrolled mode, per the `@base-ui/react/checkbox` `Checkbox.Root` API that `CheckboxPrimitive.Root` forwards (`checkbox.tsx`, `React.ComponentProps<typeof CheckboxPrimitive.Root>`). The wrapper exposes only the controlled `value`/`onChange` pair and does not forward `defaultChecked`; see the Design Decision on required `value` and `onChange`.
- **hint-description-association**: In the Wrapper, when a hint is given, the component MUST give the hint element the id `<field id>-hint` and set the input's `aria-describedby` to that id (or the platform equivalent, e.g. WinUI's `AutomationProperties.DescribedBy`), so assistive technology announces the hint when the input receives focus. With no hint, the input carries no `aria-describedby`.
